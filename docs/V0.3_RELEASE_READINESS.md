## Evidence and limits

The candidate preserves the accepted IndexedDB/migration foundation and wallet UX.
Focused regressions cover acknowledgment of an earlier commit while later notes
compete with another device, durable missing-row recovery, restart and subsequent
acknowledgments. Competing field alternatives are retained; missing rows acquire
semantic recovery intent and balance uncertainty rather than disappearing later.

`npm test` exercises production reducers and Google adapters with synthetic data.
`npm run test:worker` loads the production module graph and HTTP DO class in
Miniflare/workerd at the checked-in `2026-06-11` compatibility date, using real
SQLite storage. It exercises legacy-client fencing, exact owned-Sheet routing,
principal mismatch rejection, concurrent writers across external awaits, and
actual runtime teardown/restart after possible dispatch. Unmatched outbound
traffic is denied. Google responses remain mocked: no live principal, owner,
permission, session secret, remote namespace or cost claim follows from this.

The integrated Chromium cycle uses real React/IndexedDB, synthetic APIs and the
production reconciliation/coordinator code. It covers 412 × 923 and desktop.
Accepted native IndexedDB/manual checks are retained, not repeatedly rerun.

## Dependency advisory disposition

Audit all dependencies, not only those classified as production by npm: the
manifest historically placed build tools alongside browser dependencies. The
deployed assets do not start a Vite, PostCSS, Miniflare or Node server. The Worker
uses project modules and native platform APIs, not these npm tooling packages.

| Findings | Actual exposure and correction |
| --- | --- |
| Vite file/deny traversal, cross-origin dev-server reads and editor handling; esbuild dev-server CORS | Development server exposure, not the static wallet or Worker. Upgrade Vite 5.4.11 to patched 6.4.6, its smallest patched supported major; retain the existing SWC plugin and move Vite to devDependencies. Keep forwarded dev ports private and never attach live credentials to synthetic QA. |
| PostCSS / source-map-js traversal and malformed-map resource exhaustion | CSS/source-map processing during development/build; the wallet does not compile imported user CSS. Patch PostCSS to 8.5.33 and source-map-js to 1.2.4. |
| Browserslist / baseline-browser-mapping resource exhaustion and malformed stats | Build target/config processing; not browser inventory input. Patch to 4.29.6 / 2.11.0 or newer compatible locked versions. |
| nanoid / selector-parser generator or parsing resource exhaustion | Build tooling paths, not card/Batch operation identities. Patch to 3.3.20 / 6.1.6. Wallet identities continue using Web Crypto UUIDs. |
| New local runtime's pinned sharp / undici | Development-only Miniflare initially brought vulnerable fixed transitive versions. Same-major overrides pin sharp 0.35.5 and undici 7.30.1. Runtime tests exercise the overridden HTTP mock API; image processing is unused. Remove overrides when the upstream pins catch up. |

The final install/audit reports **zero known advisories**. This is registry evidence,
not a security certification. No React, merchant helper, OAuth scope or runtime
dependency was added. Miniflare is one development-only local compatibility tool;
its platform binaries and HTTP/image support account for the lockfile expansion.
No parallel test server, generalized conflict system or extra cloud database exists.
Audit source: project `npm audit --json`, 2026-11-25. Advisory links are provided by
the registry, including [Vite](https://github.com/advisories/GHSA-4w7w-66w2-5vf9),
[PostCSS](https://github.com/advisories/GHSA-r28c-9q8g-f849), and
[esbuild](https://github.com/advisories/GHSA-67mh-4wv8-2f99).

6. **Complete M2 acceptance through ordinary wallet use.** Do not simulate

## Recovery and rollback

- **Routine conflicts:** review progressively disclosed alternatives in Settings.
  Choose a still-applicable field/PIN alternative explicitly. A recovered missing
  row is kept with its credentials and needs fresh balance verification; accepting
  the recovery item does not verify its balance. Deletions require shared maintenance
  and exact confirmed identities. Never infer deletion from absence or matching amounts.
- **Direct Sheet editing:** pause shared maintenance first, take the private backup,
  then edit Cards only. Preserve managed `_META` commit/evidence/tombstones. Resume
  explicitly; optionally confirm exact removed identities. An external editor that
  ignores the pause can still race Google writes; stop such editing before recovery.
- **Uncertain dispatch:** keep local pending/flight state and the DO namespace.
  Use Sync now to seek the same commit ID plus matching actual content. Absence of
  a marker, elapsed time or a successful read does not prove a failed write cannot
  complete. Do not clear flights, regenerate IDs or reissue the write. If proof never
  arrives, keep affected Sheet writes stopped, export device/Sheet recovery backups,
  and have an authorized operator establish dispatch quiescence and reconcile
  privately before creating any recovery commit. No automatic bypass is implemented.
- **Expired undispatched baseline:** use explicit safe recovery only when the server
  attests not-dispatched; original operations are archived. This cannot release an
  uncertain dispatched flight. Evidence exceeding 38 KB also stops writes and needs
  private backup plus controlled operator cleanup; tombstones do not expire.
- **Rollback:** stop clients/writes; pause shared maintenance when commit recovery
  permits it. Preserve IndexedDB, all outboxes/ledgers, Sheet `_META`, DO receipts and
  bindings. Prefer a forward fix or a compatible fenced/read-only recovery build.
  Do not roll back to the historical writable Worker/client, replace a live inventory
  from a stale CSV, rotate away the only recovery state, delete the DO namespace or
  clear local storage. Restore backups only through explicit reviewed reconciliation.

Accepted evidence and the remaining external gates are recorded in the milestones
above. Local runtime and synthetic tests do not establish live Google behavior.
