# V0.3 activation and recovery plan

This is the consolidated operator plan, not authorization to provision, activate
paid services, access user data, merge or deploy. Protocol authority remains
[Architecture](ARCHITECTURE.md); [QA](QA_TEST_CHECKLIST.md) owns repeatable tests.
Complete the external steps below only under separate release authorization.

### Authorized activation preparation (2026-11-25)

The operator has authorized activation and confirmed private device CSV/complete
Sheet backups, suspended editing, Free-plan SQLite DO entitlement, Google
connectivity and existing secret bindings. Read-only production metadata confirms
the exact KV namespaces/routes, current Worker version
`4a6c6a87-003c-4883-966d-0f9a69156990`, no prior DO namespace/migration, query-string
redaction, disabled invocation logs and disabled traces. No secret values were read.
Wrangler config retains these settings and appends migration
`gc-wallet-v0.3-sqlite-20261125`. Pages builds use the same Node 24 baseline as CI.

Initial deployment must keep `SYNC_ACTIVATION_BLOCKED="true"`. The Worker still
verifies principal and exact Drive ownership, but cannot read/write card inventory
or initialize a Sheet. Status reports coordination unavailable. A focused workerd
test proves the pause across pull/commit/setup and rejects a nonowned Sheet.
Only set the flag to `"false"` after controlled Google gates pass; then deploy the
unpaused matching Worker before merging/publishing the matching frontend.
Configuration and dry-run evidence do not establish an actual deployment.

Standard CLI path is pinned Wrangler 4.168.0: `wrangler login --device`,
`wrangler whoami`, then `wrangler deploy --config worker/wrangler.toml --keep-vars`
with the reviewed SHA in the version message. Use the existing account and Worker;
never use temporary/claim deployments, another authentication mechanism, or pasted
API tokens. Confirm names/presence of retained secrets and verify observability,
migration tag, binding namespace, routes and deployed version after uploading.

### One integrated operator cycle

1. Complete standard Wrangler device sign-in in the shared environment when ready.
   Device codes expire after five minutes; rerun the same login command for a new
   code rather than sending any credentials through chat. Confirm only “signed in”.
2. While the deployed activation pause remains true, use a private browser with an
   authorized Google test account and an existing app-accessible synthetic Sheet
   containing no live cards. Connect/reconnect using the normal same-origin OAuth
   flow. Check authenticated status and stable principal in browser memory; report
   only pass/fail, never the session cookie, Google tokens or inventory.
3. A protected pull against the exact owned synthetic Sheet must return
   `503 / activation_pending` after ownership verification. A Sheet belonging to
   the other test account must be rejected by the ownership check or Google access
   denial, not return activation_pending. No Cards content is read in either case.
   Switch test accounts in the same browser and verify a different principal with
   no inherited Sheet/refresh context; reconnecting the same account must still work.
4. Report these outcomes together. Only after they pass, clear the pause through
   the reviewed Wrangler config and deploy the matching Worker, then merge the
   matching frontend and verify Pages. Keep other device editing suspended until
   the agent confirms those deployment checks.
5. In the same focused cycle, check two-device synthetic additions/notes and a
   competing balance, reload/reconnect, then one applicable verification and scanner
   check. Confirm pending work drains and alternatives remain private/recoverable.
   Retain accepted unaffected CSV/Batch/mobile checks rather than rerunning them.

If a test account has no app-accessible synthetic Sheet, prepare it before changing
production or stop for that operator setup. Do not disable the activation pause
just to create a test fixture, point testing at the live inventory, or broaden scope.

## Evidence and limits

The candidate preserves the accepted IndexedDB/migration foundation and wallet UX.
Focused regressions cover acknowledgment of an earlier commit while later notes
compete with another device, durable missing-row recovery, restart and subsequent
acknowledgments. Competing field alternatives are retained; missing rows acquire
semantic recovery intent and balance uncertainty rather than disappearing later.

`npm test` exercises production reducers and Google adapters with synthetic data.
`npm run test:worker` loads the production module graph and HTTP DO class in
Miniflare/workerd at the checked-in `2026-06-11` compatibility date, using real
SQLite storage. It exercises legacy-client fencing, exact owned-Sheet routing,
principal mismatch rejection, concurrent writers across external awaits, and
actual runtime teardown/restart after possible dispatch. Unmatched outbound
traffic is denied. Google responses remain mocked: no live principal, owner,
permission, session secret, remote namespace or cost claim follows from this.

The integrated Chromium cycle uses real React/IndexedDB, synthetic APIs and the
production reconciliation/coordinator code. It covers 412 × 923 and desktop.
Accepted native IndexedDB/manual checks are retained, not repeatedly rerun.

## Dependency advisory disposition

Audit all dependencies, not only those classified as production by npm: the
manifest historically placed build tools alongside browser dependencies. The
deployed assets do not start a Vite, PostCSS, Miniflare or Node server. The Worker
uses project modules and native platform APIs, not these npm tooling packages.

| Findings | Actual exposure and correction |
| --- | --- |
| Vite file/deny traversal, cross-origin dev-server reads and editor handling; esbuild dev-server CORS | Development server exposure, not the static wallet or Worker. Upgrade Vite 5.4.11 to patched 6.4.6, its smallest patched supported major; retain the existing SWC plugin and move Vite to devDependencies. Keep forwarded dev ports private and never attach live credentials to synthetic QA. |
| PostCSS / source-map-js traversal and malformed-map resource exhaustion | CSS/source-map processing during development/build; the wallet does not compile imported user CSS. Patch PostCSS to 8.5.33 and source-map-js to 1.2.4. |
| Browserslist / baseline-browser-mapping resource exhaustion and malformed stats | Build target/config processing; not browser inventory input. Patch to 4.29.6 / 2.11.0 or newer compatible locked versions. |
| nanoid / selector-parser generator or parsing resource exhaustion | Build tooling paths, not card/Batch operation identities. Patch to 3.3.20 / 6.1.6. Wallet identities continue using Web Crypto UUIDs. |
| New local runtime's pinned sharp / undici | Development-only Miniflare initially brought vulnerable fixed transitive versions. Same-major overrides pin sharp 0.35.5 and undici 7.30.1. Runtime tests exercise the overridden HTTP mock API; image processing is unused. Remove overrides when the upstream pins catch up. |

The final install/audit reports **zero known advisories**. This is registry evidence,
not a security certification. No React, merchant helper, OAuth scope or runtime
dependency was added. Miniflare is one development-only local compatibility tool;
its platform binaries and HTTP/image support account for the lockfile expansion.
No parallel test server, generalized conflict system or extra cloud database exists.
Audit source: project `npm audit --json`, 2026-11-25. Advisory links are provided by
the registry, including [Vite](https://github.com/advisories/GHSA-4w7w-66w2-5vf9),
[PostCSS](https://github.com/advisories/GHSA-r28c-9q8g-f849), and
[esbuild](https://github.com/advisories/GHSA-67mh-4wv8-2f99).

## Ordered activation — external authorization required

1. **Preserve recoverability before changing production.** Stop other wallet sessions
   from editing. Export each device's saved compartment CSV and original/quarantine
   recovery JSON; these contain credentials. Save privately with restricted access,
   outside Git, issue comments, test traces and cloud logs. Preserve a private Sheet
   copy including Cards and all `_META` rows. Record the reviewed client/Worker SHA,
   card identities/counts, Sheet identity and current commit/version evidence.
   Never clear browser storage or overwrite unbound inventories to prepare rollout.
2. **Resolve the production configuration and entitlement.** Review the exact
   account, Worker and environment. Keep existing private `SESSIONS` and `OAUTH_STATE`
   KV bindings; use the verified resource identifiers in approved configuration.
   Add `SHEET_COORDINATOR` bound to exported `SheetCoordinator` and one unique
   migration tag with `new_sqlite_classes = ["SheetCoordinator"]`. Preserve the
   namespace and migration history thereafter. Confirm current SQLite DO service
   entitlement, limits and expected personal-use cost; no automatic paid activation.
   Retain the locally tested compatibility date unless separately tested otherwise.
   Verify same-origin `/api/*` and `/auth/*` routes reach this coordinated Worker.
3. **Verify configuration without revealing credentials.** Confirm binding names,
   presence and environment placement for `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`
   and `SESSION_SECRET`; preserve session-signing continuity or intentionally require
   reconnect. Verify exact `FRONTEND_ORIGIN` and `REDIRECT_URI`, HTTPS callback and
   HttpOnly/Secure/SameSite session behavior. Never print values, tokens or cookies.
   Any diagnostics/observability must redact request bodies, card/PIN data and
   Authorization/Cookie headers; use commit IDs, error codes and counts only.
4. **Verify Google behavior with explicitly authorized test accounts/files.** Under
   the existing drive.file scope, prove `about.user.permissionId` is present/stable
   across reconnect and token refresh and differs between accounts. Prove an exact
   test Sheet returns matching owner.permissionId, ownedByMe and spreadsheet MIME
   type; reject nonowned/shared-only, trashed, ambiguous and wrong-account targets.
   Switch accounts in the same browser: no refresh grant or Sheet may be inherited.
   Also check the same account reconnect path with no newly issued refresh token.
   If required identity/ownership evidence is unavailable, **hold activation**;
   do not fall back to email, cached ownership, new scopes or relaxed checks.
5. **Coordinate release.** Publish the reviewed Worker with the correct bindings
   before enabling the matching frontend. Old clients must receive upgrade fencing;
   their local data remains intact. Do not offer an old uncoordinated write route
   during transition. Publish only the tested static build through the existing
   hosting process. Bind the exact test/owner Sheet, review compartment identities,
   then explicitly recover an unbound inventory only after a private backup and a
   fresh matching account/Sheet check. Samples never upload automatically.
6. **Run one small real-device acceptance cycle.** Use two devices and synthetic
   cards in an authorized private test Sheet. Check independent additions/notes,
   concurrent balances with remote provisional value and retained alternatives,
   reload/offline/reconnect, CSV/recovery export, Batch partial/exact replay and one
   controlled maintenance pause/resume. Use one genuine authorized balance check
   to confirm uncertainty clears and date-only metadata/used state stay correct.
   Review Cards → Checkout → Settings, scan readability and touch/focus behavior at
   412 × 923 and desktop. Confirm all devices converge and pending work drains.
   Do not simulate ambiguous Google writes by blindly repeating live requests.

## Recovery and rollback

- **Routine conflicts:** review progressively disclosed alternatives in Settings.
  Choose a still-applicable field/PIN alternative explicitly. A recovered missing
  row is kept with its credentials and needs fresh balance verification; accepting
  the recovery item does not verify its balance. Deletions require shared maintenance
  and exact confirmed identities. Never infer deletion from absence or matching amounts.
- **Direct Sheet editing:** pause shared maintenance first, take the private backup,
  then edit Cards only. Preserve managed `_META` commit/evidence/tombstones. Resume
  explicitly; optionally confirm exact removed identities. An external editor that
  ignores the pause can still race Google writes; stop such editing before recovery.
- **Uncertain dispatch:** keep local pending/flight state and the DO namespace.
  Use Sync now to seek the same commit ID plus matching actual content. Absence of
  a marker, elapsed time or a successful read does not prove a failed write cannot
  complete. Do not clear flights, regenerate IDs or reissue the write. If proof never
  arrives, keep affected Sheet writes stopped, export device/Sheet recovery backups,
  and have an authorized operator establish dispatch quiescence and reconcile
  privately before creating any recovery commit. No automatic bypass is implemented.
- **Expired undispatched baseline:** use explicit safe recovery only when the server
  attests not-dispatched; original operations are archived. This cannot release an
  uncertain dispatched flight. Evidence exceeding 38 KB also stops writes and needs
  private backup plus controlled operator cleanup; tombstones do not expire.
- **Rollback:** stop clients/writes; pause shared maintenance when commit recovery
  permits it. Preserve IndexedDB, all outboxes/ledgers, Sheet `_META`, DO receipts and
  bindings. Prefer a forward fix or a compatible fenced/read-only recovery build.
  Do not roll back to the historical writable Worker/client, replace a live inventory
  from a stale CSV, rotate away the only recovery state, delete the DO namespace or
  clear local storage. Restore backups only through explicit reviewed reconciliation.

External gates are deployed configuration/entitlement, real Google identity/owner
behavior, secret/session continuity and the focused authorized device/merchant
cycle. Local runtime and synthetic tests cannot establish these gates.
